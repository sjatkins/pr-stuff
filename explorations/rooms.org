The world's geography: rooms, exits, sectors, zones and resets. Read
from =src/= at commit 94876a77 and =world/=.

See also: [[file:game-engine-loop.org][game-engine-loop.org]] (the pulse
that ages zones and fires room events), [[file:mobs.org][mobs.org]]
(what zone resets load into rooms, wandering and hunting across them),
[[file:objects.org][objects.org]] (floor objects and zone saves),
[[file:players.org][players.org]] (load rooms, rentable rooms, the void). Earlier extractor notes: [[file:zones.org][zones.org]], [[file:sectors.org][sectors.org]], [[file:combat.org][combat.org]] (peaceful and arena rooms), [[file:spells.org][spells.org]] (no-magic rooms).

* A room (=room_data=, =h/structs.h:391=)
:PROPERTIES:
:CUSTOM_ID: a-room
:END:

| group      | fields                                                                                   |
|------------+------------------------------------------------------------------------------------------|
| identity   | =number= (the vnum; rooms are hashed in =room_db= by it), =name=, =description=, =ex_description= (keyword extras), =zone= |
| kind       | =sector_type= (below), =room_flags= (below), =size=, =max_people= (0 = unlimited), =parent= |
| light      | =light= (count of lit light sources present), =dark= (magical darkness count); see [[#light-and-dark]] |
| movement   | =exits= (linked list of =room_exit=), =river_speed= and =river_dir=, =tele_targ=, =tele_time=, =tele_look= |
| tracking   | =track[]= (ring of up to =max_tracks= footprints: who, when, which way) |
| live state | =contents= (objects on the floor), =people= (characters here), =visited=, =map= (cached minimap), =funct= (special procedure) |

As with mobs and objects, the occupant lists are intrusive singly linked
lists threaded through the characters and objects themselves
([[file:mobs.org::#no-instance-identity][mobs.org, "No instance identity"]]).

** Exits (=room_exit=)
:PROPERTIES:
:CUSTOM_ID: exits
:END:

Direction =num= (north, east, south, west, up, down and more; =go= and
=enter= use named exits), =to_room=, =keyword= and
=general_description= for =look <dir>=, =exit_info= flags (below),
=default_state= and =reset_time= for doors that reset, =key= (object
vnum), a position and width used by the map, and the Mastermind
=mm_crack_code= for crackable doors (same minigame as containers,
[[file:objects.org::#flags][objects.org, container flags]]).

Exit flags (=EX_*=, =h/const.h:472=): door, closed, locked, secret,
pickproof, knockable, hidden, message, autoclose, autolock, crackable.
A door with a =reset_time= gets an =EVT_DOOR= event at boot and after
every change, returning it to =default_state= when the time is up
([[file:game-engine-loop.org::#the-event-system][engine, "The event system"]]).

In the world file:

#+begin_example
  exits {
    to { n, 0 }
    to { 11, Wasteland:12 }       ; a named direction into another zone
      key { 4514 }
      info { door, closed, autoclose, locked, autolock }
      keywords { Greece }
  }
#+end_example

Room numbers in a zone file are offsets from the zone's range start;
=Zone:N= reaches into another zone.

** Sectors (=SECT_*=, =world/SECT/sectors.current=)
:PROPERTIES:
:CUSTOM_ID: sectors
:END:

Thirty types in code (inside, city, field, forest, hills, mountain,
swimmable and unswimmable water, air, underwater, fire, cold, desert,
arctic, road, bracken, thicket, prototype, beach, temple, bridge, the
winter variants, swamp, swamp road, mud, astral) and a data file per
sector giving, for normal and flying movement, the move-point cost,
the delay in pulses before the next move, the base chance of leaving
tracks, flags such as =water_breath= and =no_weather=, an entry damage
formula, and the minimap glyphs and colours. Sector 83 is =noshowmap=.
Fire, cold and similar sectors also hurt unprotected players every 4 s
([[file:game-engine-loop.org::#periodic-work-keyed-to-the-pulse-count][engine, periodic work]]).

Per-sector values as extracted are tabulated in [[file:sectors.org][sectors.org]]. Of the 26,284 rooms in the source files, 10,001 are sector
=Prototype=, builders' placeholders.

* Light and dark
:PROPERTIES:
:CUSTOM_ID: light-and-dark
:END:

=IS_DARK(room)= is "no lit light source here, and the room is flagged
=DARK= or has magical darkness". =light= is a counter: a character
entering with a lit light in the light slot increments it
(=handler.c:3418=), leaving decrements it, lights burning out
decrement it ([[file:objects.org::#the-per-object-tick][objects, per-object tick]]).
Outdoor rooms also follow the sun through =weather_and_time=.

* What you see (=look_room=, =look.c:869=)
:PROPERTIES:
:CUSTOM_ID: what-you-see
:END:

Room name (coloured), a blue-glow marker, flags for immortals, the
description, the minimap if =CONFIG_MAP= (=do_map auto=, drawn from
exit geometry and the sector glyphs), objects on the floor, characters
present, then the exit list unless =NOSHOWEXIT=, and the freshest set
of tracks if the viewer can track ("Some very fresh tracks lead
west."). This is the single room-display entry point, which is why the
web plan hangs its room marker there ([[file:../SUMMARY.md][SUMMARY §14]]).

* Moving between rooms (=do_move=, =move.c:735=)
:PROPERTIES:
:CUSTOM_ID: moving-between-rooms
:END:

In order: refuse while falling, held by vines, or in too crowded a
room to flee; run the room's and the mobs' =SPEC_MOVE= specials, which
may block ([[file:mobs.org::#special-procedures][mobs, specials]]);
check the exit exists and is not closed or secret; check sector
requirements (boats on unswimmable water, water breathing underwater,
flight for air); check the target's =max_people= and =PRIVATE= limits
including followers; charge move points by sector and impose the
sector's delay; leave tracks with the sector's probability;
=char_from_room= / =char_to_room=, which bumps the light count and, on
arrival, schedules the room's teleport or river event if it has one
(=handler.c:3422=); then =look=. Followers move after the leader. A
=DEATH= room ends the trip with =death_trap=; a =FALL= room with an
open exit down starts an =EVT_FALLING= chain that speeds up the further
you fall.

Teleport rooms move everyone who stands in them to =tele_targ= after
=tele_time= quarter-seconds, with =tele_look= deciding whether they
look on arrival. River rooms push occupants =river_dir= every
=river_speed= quarter-seconds.

* Zones (=Zone=, =h/zone.h:70=; =world/ZONE/*.zon=)
:PROPERTIES:
:CUSTOM_ID: zones
:END:

The extracted zone data and its shape are in [[file:zones.org][zones.org]].

A zone is a name, a vnum =range=, an optional =save= range, a
=reset_type= and =reset_freq=, a current =age=, a =zone_limit= list
(maximum of each mob vnum alive in this zone), a =boot_only= command
list, and the reset =cmds=.

#+begin_example
ZONE "Abyss"
  range (25000-25125)
  save (25000-25125)
  reset (always, 27)
  zone_limit { 10 mob 25005  7 mob 25016 ... }
  boot_only { in 101 load obj 25102 }
  in (0 & 25 & 27 & 29) load mob 25005
  in (3 & 11) load atmost 2 mob 25017 with { 10% obj 25017 }
  in 12 load mob 25014 with { 15% obj 25016  obj 25050  1% obj 25018 }
#+end_example

The grammar (=Zone/parser.y=) has =in= with single rooms, lists and
ranges, =load=, =loadgroup=, =atmost= and =upto= counts, =with= and
=containing= for equipment and contents chains, per-item
probabilities, =requires=, =repeat=, and =chain=.

** Ageing and reset
:PROPERTIES:
:CUSTOM_ID: ageing-and-reset
:END:

Every 60 s =zone_update= ([[file:game-engine-loop.org::#periodic-work-keyed-to-the-pulse-count][engine, periodic work]])
increments every zone's =age=; when it reaches =reset_freq= the zone
resets if its type is /always/ (2), or /ifempty/ (1) and no player is
in it; type /never/ (0) only resets at boot. =reset_zone= (=zone.c:834=)
logs "Reset zone <name>" (the line that is 99% of the log), zeroes the
age, and runs the commands: for each, count what is already there,
load the shortfall up to the limits, roll each probability
([[file:mobs.org::#loading-and-limits][mobs, loading]],
[[file:objects.org::#where-objects-come-from][objects, where from]]).
=zreset= does it on demand; =show zones= lists ages and lifespans.

** Saving (=world.save.c=, =SaveZone=)
:PROPERTIES:
:CUSTOM_ID: saving
:END:

Every 10 s one zone with a =save= range is written to
=WorldSave/zone.N= (=room.save.c= =WriteRoom=): for each room in the
range, every exit whose state differs from its default (flags, crack
code and attempts), the room flags, every /mob/ standing in it
(=mob.save.c= =SaveMob=: prototype vnum, stats, hit points, gold,
position, affect bits, armour, inventory and equipment, affects and
pulse affects) and every object on the floor. The limited-item world
counts go to =WorldSave/Misc/limited.obj=. At boot these load after the
world file (=LoadMob= creates the mob from its prototype and overlays
the saved fields), so dropped items, door states and the mobs of
saveable zones survive a reboot; mobs anywhere else do not.
=lib/BOOT_CLEAN= makes the next boot discard them. Extracted form:
=py_json/out/worldsave.jsonl= and =limited.jsonl=.

** Live room edits
:PROPERTIES:
:CUSTOM_ID: live-room-edits
:END:

Builders edit rooms in game with =redit= (=I2=) and write a range of
rooms to a file with =rsave <file> <lo> <hi>=. Files placed in
=lib/UPDATE/= are loaded at boot after =world.out= and override those
rooms ("Loading updated rooms", "UPDATE/NewWarg100410:32 rooms"),
which is how a room change reaches production without recompiling the
world. The world repo is still the source of truth for everything
else.

* Room specials
:PROPERTIES:
:CUSTOM_ID: room-specials
:END:

18 C functions in =spec_rooms.c=, bound by vnum in =assign_rooms=. A
room special is the first thing consulted for any command issued in
the room ([[file:mobs.org::#special-procedures][dispatch order]]), so it
can intercept movement, speech, or anything else.

* Quirks
:PROPERTIES:
:CUSTOM_ID: quirks
:END:

- =light= is a counter maintained by hand on every enter, leave, wear,
  remove and burn-out; a mismatch leaves a room permanently lit or
  dark until reboot.
- Sector 17, =Prototype=, is 38% of all rooms.
- Tracks are a small ring per room; busy rooms forget quickly.
- The map is cached per room in =map= and regenerated on demand.
- =max_people= counts followers against the leader, so a group can be
  refused a room that one of them could enter.
- Room specials, like mob and object specials, are C functions by
  vnum; there is no scripting for rooms either.
